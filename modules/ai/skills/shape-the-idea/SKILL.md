# Shaping an Idea

The user has an idea that is not complete, or only a feeling that something is wrong. Your job is to make it concrete,
so that the user can decide what they want.

Do not change anything (files, commits, messages) until the user tells you to start. Do not ask if you should start.

## 1. Find the principle

Read all the things that the idea touches, and the things that are related to them. Then find the principle under the
idea.

This is the most important step. The points of the user are often parts of one idea that they did not name yet, and
this idea is often what they are looking for. Find what the points have in common. Make sure that the principle
explains all of them. Then use it to find the parts of the current state that disagree with it.

If you are not certain, give the possible principles. Do not make one up.

## 2. Present it

Give these, in this order. Leave out the ones that have nothing important to say.

1. The principle: how each point of the user fits it.
2. The problems in the current state that it shows.
3. The directions: if there is more than one, recommend one.
4. A draft of what the result can look like.
5. The effects that the user did not mention, for example a rule that the idea disagrees with.
6. The open questions, each with your recommendation.

## 3. Continue the discussion

- Change the draft to agree with each reply. If only a small part changes, show only that part.
- Make sure that the principle still explains all the points, also the new ones.
- If the user does not answer a question, use your recommendation and say so.
- If the user is correct, say so. Do not defend a point only because you made it.
- After each change, look for parts of the draft that are now unnecessary.

## 4. Start the work

When the user tells you to start, do the last draft that the user saw, and nothing more.
